# Пятница 2

Персональный Telegram-помощник для наблюдения за спотовым рынком, бумажных
сделок и отдельного журнала фактических ручных сделок. Доступны Binance и OKX.
Бот использует публичные рыночные данные. Для расчётов биржевой ключ не нужен.

## Запуск

1. Установите Python 3.13 и зависимости через `python -m pip install -r requirements.txt`.
2. Скопируйте `.env.example` в `.env`. Заполните `TELEGRAM_TOKEN` и числовой
   `BOT_OWNER_ID`. Команды принимаются только от владельца в личном чате.
3. Укажите нужные площадки в `SIGNAL_EXCHANGES` и ставку комиссии за одну
   сторону в `PAPER_FEE_RATE` как долю. Например, `0.002` означает 0,2%.
4. Запустите `python bot.py`. В Telegram введите `/setup 1000 300` для
   настройки условного капитала и бюджета и `/resume` для запуска поиска.
   Суммы здесь приведены для примера бумажного прогона.

| Команда | Действие |
| --- | --- |
| `/status` | Состояние сканера и котировок |
| `/stop` | Пауза новых карточек с сохранением сопровождения |
| `/watch` | Сетапы в наблюдении, допустимая цена или причина ожидания |
| `/report` | Результаты бумажного портфеля и теневых экспериментов |
| `/positions` | Открытые бумажные позиции и их ID |
| `/close_paper ID` | Бумажное закрытие по свежей цене продажи |
| `/manual_open БИРЖА ПАРА ОБЪЁМ ЦЕНА КОМИССИЯ_USDT` | Записать фактическую покупку |
| `/manual_close ID ОБЪЁМ ЦЕНА КОМИССИЯ_USDT` | Записать фактическую частичную или полную продажу |
| `/manual` | Ручные позиции и реализованный результат |

В `/report` за последние 24 часа отдельно видны кандидаты, входы с
подходящей котировкой, доставленные карточки и подтверждённые покупки.
Медиана задержки считается от первой зафиксированной подходящей котировки
до отправки карточки. Чистый результат за окно включает все исполнения
позиций, которые закрылись за эти 24 часа, включая комиссии. Он показан
отдельно от общей просадки портфеля. Перед отправкой карточки проверяется
текущий лимит капитала и риска, а при подтверждении журнал проверяет его
повторно в транзакции.

Для бумаги используются лучшие цены и доступные количества в стакане.
Если свежих данных или объёма нет, позиция ждёт подходящую котировку.
Пересечение стопа моделируется по наблюдаемому bid. Издержки учитываются
на обеих сторонах. Модель исполнения не восстанавливает неизвестные
внутрисвечные цены и очередь заявок. Просадка рассчитана по сохранённым
наблюдениям капитала.

Откат и пробой показываются в наблюдении как экспериментальные стратегии.
`EXPERIMENTAL_SIGNALS=1` включает их карточки. По умолчанию отдельные карточки
выдаёт базовая стратегия.

## Теневой ИИ и хранение

Для включения ИИ задайте `TRADE_REVIEW_ENABLED=1`, `TRADE_REVIEW_MODEL`,
`TRADE_REVIEW_KEY` и полный HTTPS `TRADE_REVIEW_URL` совместимого провайдера
Chat Completions с JSON mode. Во внешний запрос попадают данные кандидатов
и параметры открытых позиций теневого бумажного портфеля. Оценка ИИ сохраняется вместе с задержкой.
Telegram продолжает получать сигналы по правилам при недоступной модели.
В отчёте представлены независимые бумажные портфели базового отбора, более
строгого фильтра, ИИ, отката и пробоя. У строгого варианта фиксированные
правила отбора. Дневной лимит реализованных потерь считается по UTC.
Сравнивайте число закрытых позиций, P&L и просадку за сопоставимый период.

Храните `PAPER_DB` и соседние базы экспериментов на постоянном диске приложения.
При старте бот архивирует старый `portfolio.json` в SQLite без изменения
исходника. Старые открытые записи без надёжной площадки надо сверить вручную.
После перезапуска действующие бумажные позиции сопровождаются автоматически.
Запуск поиска требуется подтвердить через `/resume`.

Пример согласованной резервной копии главной базы:

```python
from paper_ledger import PaperLedger

PaperLedger("data/paper.sqlite3").backup("data/paper-backup.sqlite3")
```

Для диагностики и принципов защитной проверки см. [инженерные образцы](docs/references.md).

Для прежних автономных модулей анализа и графиков доступен отдельный набор
зависимостей в `requirements-legacy.txt`.

## Живые новостные сигналы

`news_live` следит за официальными мировыми публикациями и распознаёт
макроданные, решения центробанков, международную торговлю и санкции,
геополитику, энергетику, корпоративные события, сбои инфраструктуры и
стихийные бедствия. Охват зависит от подключённых лент. Для публикаций
за последние 90 минут из доступных лент сервис измеряет рост, снижение
или отсутствие движения на закрытых свечах после подтверждения и
показывает разницу с BTC за тот же период. Измерение описывает движение
цены во времени. Причинная связь с новостью требует отдельной проверки.

Первоисточники включают пресс-службу ООН, Еврокомиссию, EIA, BEA, SEC,
NVIDIA, ФРС, ЕЦБ, BLS, Банк Англии и Банк Японии. Ленты BBC World
и Le Monde добавляют поводы для сверки в раздел `discovery_candidates`
отчёта. Рыночный расчёт и торговый разбор используют публикации
из первоисточников.

К торговому разбору допускаются конкретные релизы ФРС, ЕЦБ, BLS, Банка
Англии, Банка Японии и BEA. Дополнительно проверяются тренд, лучший бид и аск,
объём и комиссии. Рекомендации относятся к спотовым парам к USDT на OKX
или Binance. Публикации и измерения сохраняются в `data/live/news-live.sqlite3`.

```sh
python -m pip install -r requirements.txt
python -m news_live --once
python -m news_live --report
```

`--once` выполняет один цикл. Без этого флага сервис опрашивает ленты
не чаще одного раза в минуту. Вывод содержит строки JSON с состоянием
источников, измерениями `market_reaction`, причинами наблюдения, сигналами
и обновлениями их статуса.
`--report` показывает журнал без сетевых запросов. Для постоянного
запуска храните `--data-dir` на постоянном диске.

Для режима с агентами задайте `TRADE_REVIEW_URL` (полный HTTPS-адрес Chat
Completions с поддержкой JSON mode), `TRADE_REVIEW_KEY` и
`TRADE_REVIEW_MODEL`. Укажите свой капитал и лимит сценарного риска в
USDT, а комиссию за сторону в виде доли. Команда ниже показывает формат
запуска с переменными, которые задаёт оператор.

```sh
python -m news_live --venue okx --symbols BTC/USDT ETH/USDT \
  --budget "$LIVE_BUDGET" --fee-rate "$LIVE_FEE" --risk-cap "$LIVE_RISK_CAP" \
  --history-file "$LIVE_RECORDED_FILLS" --team --concurrency 50
```

Финальная проверка запускается после положительной оценки сопоставимой
истории. По умолчанию проводится один разбор за цикл. Флаг
`--max-reviews-per-scan` позволяет указать от 1 до 4. Каждый разбор
выполняет 50 отдельных запросов провайдеру. Если убрать `--concurrency 50`, параллелизм по умолчанию
ограничен десятью запросами. В модель передаются публичные рыночные
данные и сводная статистика. Ответы всех 50, большинство голосов в пользу
сигнала, отсутствие возражений, та же редакция новости и свежая котировка
обязательны. Запросы расходуют квоту провайдера.

История загружается из локального JSON-массива закрытых реальных сделок,
включая убыточные. Запись содержит:

- `strategy` (`trend_v1`), `family` (`us_monetary_policy`,
  `eu_monetary_policy`, `us_economic_release`, `uk_monetary_policy`,
  `japan_monetary_policy` или `us_income_and_outlays`),
  `venue` и `symbol`.
- `provenance` (`recorded_fill`), уникальный `outcome_id` и `event_id`.
- `event_at`, `opened_at`, `closed_at` и `available_at` в секундах Unix UTC.
  `available_at` отмечает, когда результат сделки и его связь с событием
  стали доступны для анализа.
- `risk_usdt`, `net_pnl_usdt` после фактических издержек и
  `stressed_net_pnl_usdt` после дополнительных издержек.

Для допуска требуется минимум 20 разных сравнимых событий за 10 разных
дней UTC в окне 1095 дней. Нижняя оценка результата после стрессовых
издержек должна быть положительной. За последние 180 дней нужно не меньше
трёх сравнимых событий и положительное среднее после стрессовых издержек.
При пустой или недостаточной истории сервис остаётся в наблюдении.
Подлинность и полноту локального экспорта сервис самостоятельно подтвердить
не может.

Перед проверкой командой бот сравнивает до 16 ещё не разобранных
кандидатов за раз. Нижняя историческая оценка после повышенных издержек
умножается на первоначальный риск позиции, которую сейчас допускают
стакан и лимиты. Так определяют порядок проверки по расчётному
результату в USDT. Если перед проверкой котировка кандидата просрочилась,
бот обновляет её один раз и пересчитывает приоритет. Если ни один план
из первой группы не подошёл, бот рассматривает следующую.

Сигнал содержит диапазон входа, стоп, две цели, ориентировочный размер и
потенциальный убыток по сценарию. Срок действия ограничен свежестью
стакана и моментом закрытия следующей свечи. Разрыв цены и фактическая
очередь ордеров находятся вне расчёта. Прибыльность зависит от
фактического исполнения и издержек.

### Каталог биржи и риск портфеля

`--all-pairs` получает актуальный публичный спотовый каталог выбранной
биржи и обходит его блоками до 32 инструментов за цикл. Для ручного списка
есть `--symbols`, принимающий до 16 пар к USDT. Сервис параллельно
загружает закрытые свечи и переиспользует общий
ориентир BTC. Кандидаты с сопоставимой историей ранжируются по нижней
оценке исторического результата на единицу начального риска после
стрессовых издержек. Свежий стакан проверяется у кандидата перед
разбором агентами и повторно перед отправкой. При просроченной котировке
сервис переходит к следующему кандидату. `--allocation-slots 16` ограничивает
стоимость одной позиции одной шестнадцатой капитала.

Риск и стоимость уже выпущенных сигналов резервируются в одном журнале
на пять минут. Истечение котировки в карточке завершает действие сигнала.
Суммарный риск учитывает одновременные убытки по сценариям всех открытых
позиций из снимка и более новых зарезервированных сигналов. Повторный
вход в тот же инструмент блокируется на время резерва или пока инструмент
указан в снимке открытых позиций.

Для `--team` с `--all-pairs`, `--manual-replies`, более чем четырьмя
заданными вручную парами или несколькими разборами за цикл укажите
`--portfolio-file`. Локальный JSON должен содержать:

- `observed_at` в секундах Unix UTC и `available_cash_usdt` со свободными
  USDT по состоянию на это время.
- Массив `positions` с одной записью на каждую открытую пару в пределах
  площадки. Запись включает `venue`, `symbol` и `stressed_risk_usdt`.
- Для пар с другой валютой котировки укажите доступные суммы в
  `quote_balances`, например остаток `BTC` для `ETH/BTC`. Цена входа
  и цели показываются в валюте пары. Размер риска пересчитывается в USDT
  по свежим ценам конвертации. При отсутствии остатка или свежей конвертации
  такая пара остаётся в наблюдении.

Снимок должен быть свежим в пределах пяти минут. Перед разбором и
отправкой сервис читает его заново. При ошибке или устаревшем снимке
продолжается наблюдение. Данные снимка поступают от оператора, поэтому
обновляйте их после изменений портфеля. Средства и открытые позиции
без актуального снимка сервис оценить не может.

В отчёте `--report` раздел `trade_readiness` показывает причины, по которым
пока доступно только наблюдение. Передайте те же флаги площадки, списка
пар, риска и файлов, что используются при запуске. Раздел проверяет
сопоставимость записей исполнений и свежесть портфеля локально. Статус
`candidate_review_required` означает, что исходные данные прошли
предварительные проверки. Каждый кандидат ещё проходит собственный
расчёт, проверку команды и сверку со свежим стаканом.

### Автоматический сбор рыночных наблюдений

```sh
python -m news_live --venue okx --all-pairs --collect-market-evidence --data-dir /data/live
```

В полном каталоге каждый цикл проверяются до 64 пар. До восьми мест
отводятся BTC/USDT, ETH/USDT и активным спотовым парам с высоким
суточным оборотом в USDT. Остальные пары обходятся по очереди.
Список по обороту обновляется каждые пять минут. Закрытые свечи
переиспользуются до следующего закрытия по своему интервалу.

Бот фиксирует публичный стакан кандидата после подтверждённой новости и
прохождения технического фильтра. Через 5, 15 и 60 минут он сравнивает
доступный тогда bid с исходным ask и записывает изменение цены. Окно
снятия каждого контрольного значения длится 75 секунд. Пропуск окна
отмечается в журнале. Данные и ожидаемые замеры сохраняются на постоянном
диске после перезапуска.

Отчёт `--report` показывает число наблюдений, число разных событий,
положительные и отрицательные движения, пропуски и среднее изменение
цены по каждому интервалу. Эти показатели учитывают наблюдаемый спред.
Фактические исполнения, комиссии и проскальзывание доступны только из
истории реальных сделок. Сбор публичных данных доступен без торгового
капитала и провайдера модели.

### Отправка сигналов в Telegram

Технические карточки можно включить сразу после проверки личного чата.

```sh
python -m news_live --venue okx --all-pairs --telegram --technical-signals \
  --collect-market-evidence --data-dir /data/live
```

Бот отправляет до четырёх технических карточек за цикл, когда
подтверждённая новость, закрытые свечи и свежий стакан дали подходящий
вход. Карточка содержит предельную цену, стоп, две цели, срок и
сценарное отношение результата к риску при повышенных издержках.
`--setup-fee-rate` задаёт оценку комиссии за сторону. По умолчанию она
равна 0,10%, дополнительно проверяется запас издержек 0,10% с каждой
стороны. Карточка действует до 60 секунд и до следующей закрытой свечи.
Размер позиции и подтверждённый результат сделок не рассчитываются в
этом режиме. `--report` показывает такие карточки в `technical_setups`.

#### Торговые карточки с проверкой портфеля

Владелец сначала открывает личный чат с ботом и нажимает **Start**.
Укажите `TELEGRAM_TOKEN` и числовой `BOT_OWNER_ID` в переменных окружения
сервиса. Для проверки этих настроек запустите:

```sh
python -m news_live --telegram-check
```

Статус `ready` подтверждает доступ к указанному личному чату.
Проверка не отправляет сообщение. Добавьте `--telegram` к рабочей команде
с `--team`, чтобы получать карточки подтверждённых сигналов. В сообщении
указаны источник, диапазон входа, стоп, цели, сценарный риск и время
истечения котировки по Москве. Когда срок истекает или источник
отменяет сигнал, сервис обновляет исходную карточку.

Перед разбором и отправкой бот проверяет, что результат при достижении
обеих целей покрывает риск по стопу с запасом на издержки 0,10% на сторону.
Верхняя цена в карточке равна цене, по которой рассчитан объём заявки.
В карточке видны результаты при базовых и повышенных издержках.

На Railway запустите отдельный процесс из ветки
`codex/live-news-signals` с подключённым постоянным диском. Пример команды
использует том, смонтированный в `/data`. Поместите экспорт исполнений
в `/data/live/recorded-fills.json` и задайте указанные переменные расчёта
и доступа к модели в настройках этого сервиса.

```sh
python -m news_live --telegram --team --venue okx --symbols BTC/USDT ETH/USDT \
  --data-dir /data/live --history-file /data/live/recorded-fills.json \
  --budget "$LIVE_BUDGET" --fee-rate "$LIVE_FEE" --risk-cap "$LIVE_RISK_CAP"
```

Процесс использует только отправку и обновление сообщений Telegram.
Приём команд остаётся у процесса `bot.py`, если оба используют один
токен. Просроченные сигналы пропускаются. После сетевой ошибки с
неизвестным результатом отправка того же сигнала не повторяется.
`--report` показывает счётчики доставки, а журнал процесса содержит
статусы `telegram_delivery` и `telegram_update`.

### Ответ на сигнал и очередь ручных сделок

Чтобы искать пары по всей бирже и принимать ответы владельца в Telegram,
добавьте `--all-pairs --manual-replies` к рабочей команде вместе с
`--portfolio-file /data/live/open-portfolio.json`. В этом режиме уберите
`--symbols`. Для распределения капитала между 16 позициями можно указать
`--allocation-slots 16`.

Команда из 50 агентов проверяет кандидата перед отправкой. Пока отправленная
карточка ждёт ответа, бот продолжает собирать рыночные данные и ранжировать
другие пары. Сканирование продолжается и во время проверки командой.
Команда обрабатывает один набор за раз, а в ожидании хранится только
последний набор. Если история исполнений обновилась во время проверки,
карточка по прежней оценке не отправляется. После кнопки **Вошёл** или
**Пропуск** бот начинает следующий
цикл поиска. **Вошёл** отмечает ручную сделку. **Закрыл** освобождает место
после ручного закрытия. В лимите 16 учитываются подтверждённые владельцем
позиции и открытые пары из свежего снимка. Бот сохраняет ожидание и позиции
между перезапусками. Ответы привязаны к исходной карточке и личному чату
владельца. Риск отмеченной открытой позиции учитывается до её закрытия.

`--daily-risk-cap` задаёт дневной лимит расчётного риска в USDT.
При ручных ответах он по умолчанию равен `--risk-cap`. Счётчик учитывает
позиции, подтверждённые кнопкой **Вошёл**, в том числе перенесённые с
прошлого дня. После **Закрыл** расчётный риск этой позиции остаётся в
дневной сумме до полуночи по Москве. **Пропуск** дневную сумму не увеличивает.
Старые подтверждения без даты однократно учитываются в день обновления.
Этот лимит рассчитан по сценариям стопа. Фактический убыток зависит от
исполнения и может быть выше.

Срок действия котировки и срок ожидания ответа различаются. После
истечения котировки кнопки по-прежнему доступны для учёта уже выполненной
сделки или пропуска. Выставление и закрытие ордера остаются ручными.
При неподтверждённой доставке её можно снять командой `/skip_pending`.
Для получения ответов запустите только один процесс Telegram polling
на этот токен. При существующем webhook бот сообщает об этом при запуске.

## Новостной бумажный режим

Автономный режим проверяет официальные публикации NVIDIA, ФРС, ЕЦБ и BLS,
сохраняет время получения и редакцию, затем сверяет событие с закрытыми
свечами и текущим стаканом. В первом выпуске распознаются новостные темы о
руководстве NVIDIA, денежной политике и ключевых американских макроданных.
Связь корпоративного события NVIDIA с торгуемой криптопарой остаётся
исследовательской гипотезой. Для акций NVDA потребовался бы отдельный адаптер
рыночных данных. Все исполнения в этом режиме бумажные.

```sh
python -m news_paper --once
python -m news_paper --venue okx --symbol BTC/USDT
python -m news_paper --report
```

При постоянном запуске разбор новостей и сопровождение позиций работают
параллельно. Журналы по умолчанию лежат в `data/news/`. Параметр `--data-dir`
позволяет указать постоянный диск. Для разных площадок и пар используйте
разные папки, чтобы каждый процесс сопровождал собственные позиции.

Для включения команды используйте `--team` и настройте существующие
`TRADE_REVIEW_URL`, `TRADE_REVIEW_KEY`, `TRADE_REVIEW_MODEL`. На один
допущенный разбор выполняются 50 отдельных запросов с разными ролями.
Все получают подтверждённый заголовок, рыночный снимок и сопоставимые
бумажные результаты после издержек. По умолчанию одновременно выполняются
до 10 запросов. С `--concurrency 50` допустимы все 50, если провайдер
выдерживает такую параллельность. Запросы могут расходовать квоту модели.
Пилот разбирает до одного события командой за цикл. Результаты каждого
агента сохраняются в локальном журнале.

Сигнал требует достаточной бумажной истории, положительной консервативной
оценки после издержек и повторной проверки новости и котировки после
ответов команды. До этого журнал накапливает отдельные исследовательские
исполнения. Успешный сигнал фиксируется в отдельном бумажном портфеле.
