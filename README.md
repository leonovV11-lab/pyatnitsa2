# Пятница 2

Персональный Telegram-помощник для наблюдения за спотовым рынком, бумажных
сделок и отдельного журнала фактических ручных сделок. Доступны Binance и OKX.
Бот использует публичные рыночные данные. Для расчётов биржевой ключ не нужен.

## Запуск

1. Установите Python 3.13 и зависимости через `python -m pip install -r requirements.txt`.
2. Скопируйте `.env.example` в `.env`. Заполните `TELEGRAM_TOKEN` и числовой
   `BOT_OWNER_ID`. Команды принимаются только от владельца в личном чате.
3. Укажите нужные площадки в `SIGNAL_EXCHANGES` и ставку комиссии за одну
   сторону в `PAPER_FEE_RATE` как долю. Например, `0.002` означает 0,2%.
4. Запустите `python bot.py`. В Telegram введите `/setup 1000 300` для
   настройки условного капитала и бюджета и `/resume` для запуска поиска.
   Суммы здесь приведены для примера бумажного прогона.

| Команда | Действие |
| --- | --- |
| `/status` | Состояние сканера и котировок |
| `/stop` | Пауза новых карточек с сохранением сопровождения |
| `/watch` | Сетапы в наблюдении, допустимая цена или причина ожидания |
| `/report` | Результаты бумажного портфеля и теневых экспериментов |
| `/positions` | Открытые бумажные позиции и их ID |
| `/close_paper ID` | Бумажное закрытие по свежей цене продажи |
| `/manual_open БИРЖА ПАРА ОБЪЁМ ЦЕНА КОМИССИЯ_USDT` | Записать фактическую покупку |
| `/manual_close ID ОБЪЁМ ЦЕНА КОМИССИЯ_USDT` | Записать фактическую частичную или полную продажу |
| `/manual` | Ручные позиции и реализованный результат |

В `/report` за последние 24 часа отдельно видны кандидаты, входы с
подходящей котировкой, доставленные карточки и подтверждённые покупки.
Медиана задержки считается от первой зафиксированной подходящей котировки
до отправки карточки. Чистый результат за окно включает все исполнения
позиций, которые закрылись за эти 24 часа, включая комиссии. Он показан
отдельно от общей просадки портфеля. Перед отправкой карточки проверяется
текущий лимит капитала и риска, а при подтверждении журнал проверяет его
повторно в транзакции.

Для бумаги используются лучшие цены и доступные количества в стакане.
Если свежих данных или объёма нет, позиция ждёт подходящую котировку.
Пересечение стопа моделируется по наблюдаемому bid. Издержки учитываются
на обеих сторонах. Модель исполнения не восстанавливает неизвестные
внутрисвечные цены и очередь заявок. Просадка рассчитана по сохранённым
наблюдениям капитала.

Откат и пробой показываются в наблюдении как экспериментальные стратегии.
`EXPERIMENTAL_SIGNALS=1` включает их карточки. По умолчанию отдельные карточки
выдаёт базовая стратегия.

## Теневой ИИ и хранение

Для включения ИИ задайте `TRADE_REVIEW_ENABLED=1`, `TRADE_REVIEW_MODEL`,
`TRADE_REVIEW_KEY` и полный HTTPS `TRADE_REVIEW_URL` совместимого провайдера
Chat Completions с JSON mode. Во внешний запрос попадают данные кандидатов
и параметры открытых позиций теневого бумажного портфеля. Оценка ИИ сохраняется вместе с задержкой.
Telegram продолжает получать сигналы по правилам при недоступной модели.
В отчёте представлены независимые бумажные портфели базового отбора, более
строгого фильтра, ИИ, отката и пробоя. У строгого варианта фиксированные
правила отбора. Дневной лимит реализованных потерь считается по UTC.
Сравнивайте число закрытых позиций, P&L и просадку за сопоставимый период.

Храните `PAPER_DB` и соседние базы экспериментов на постоянном диске приложения.
При старте бот архивирует старый `portfolio.json` в SQLite без изменения
исходника. Старые открытые записи без надёжной площадки надо сверить вручную.
После перезапуска действующие бумажные позиции сопровождаются автоматически.
Запуск поиска требуется подтвердить через `/resume`.

Пример согласованной резервной копии главной базы:

```python
from paper_ledger import PaperLedger

PaperLedger("data/paper.sqlite3").backup("data/paper-backup.sqlite3")
```

Для диагностики и принципов защитной проверки см. [инженерные образцы](docs/references.md).

Для прежних автономных модулей анализа и графиков доступен отдельный набор
зависимостей в `requirements-legacy.txt`.

## Живые новостные сигналы без Telegram

`news_live` следит за официальными мировыми публикациями и распознаёт
макроданные, решения центробанков, международную торговлю и санкции,
геополитику, энергетику, корпоративные события, сбои инфраструктуры и
стихийные бедствия. Охват зависит от подключённых лент. Для публикаций
за последние 90 минут из доступных лент сервис измеряет рост, снижение
или отсутствие движения на закрытых свечах после подтверждения и
показывает разницу с BTC за тот же период. Измерение описывает движение
цены во времени. Причинная связь с новостью требует отдельной проверки.

Первоисточники включают пресс-службу ООН, Еврокомиссию, EIA, BEA, SEC,
NVIDIA, ФРС, ЕЦБ, BLS, Банк Англии и Банк Японии. Ленты BBC World
и Le Monde добавляют поводы для сверки в раздел `discovery_candidates`
отчёта. Рыночный расчёт и торговый разбор используют публикации
из первоисточников.

К торговому разбору допускаются конкретные релизы ФРС, ЕЦБ, BLS, Банка
Англии, Банка Японии и BEA. Дополнительно проверяются тренд, лучший бид и аск,
объём и комиссии. Рекомендации относятся к спотовым парам к USDT на OKX
или Binance. Публикации и измерения сохраняются в `data/live/news-live.sqlite3`.

```sh
python -m pip install -r requirements.txt
python -m news_live --once
python -m news_live --report
```

`--once` выполняет один цикл. Без этого флага сервис опрашивает ленты
не чаще одного раза в минуту. Вывод содержит строки JSON с состоянием
источников, измерениями `market_reaction`, причинами наблюдения, сигналами
и обновлениями их статуса.
`--report` показывает журнал без сетевых запросов. Для постоянного
запуска храните `--data-dir` на постоянном диске.

Для режима с агентами задайте `TRADE_REVIEW_URL` (полный HTTPS-адрес Chat
Completions с поддержкой JSON mode), `TRADE_REVIEW_KEY` и
`TRADE_REVIEW_MODEL`. Укажите свой капитал и лимит сценарного риска в
USDT, а комиссию за сторону в виде доли. Команда ниже показывает формат
запуска с переменными, которые задаёт оператор.

```sh
python -m news_live --venue okx --symbols BTC/USDT ETH/USDT \
  --budget "$LIVE_BUDGET" --fee-rate "$LIVE_FEE" --risk-cap "$LIVE_RISK_CAP" \
  --history-file "$LIVE_RECORDED_FILLS" --team --concurrency 50
```

Финальная проверка запускается после положительной оценки сопоставимой
истории. Выполняется до одного разбора за цикл по 50 отдельных запросов
провайдеру. Если убрать `--concurrency 50`, параллелизм по умолчанию
ограничен десятью запросами. В модель передаются публичные рыночные
данные и сводная статистика. Ответы всех 50, большинство голосов в пользу
сигнала, отсутствие возражений, та же редакция новости и свежая котировка
обязательны. Запросы расходуют квоту провайдера.

История загружается из локального JSON-массива закрытых реальных сделок,
включая убыточные. Запись содержит:

- `strategy` (`trend_v1`), `family` (`us_monetary_policy`,
  `eu_monetary_policy`, `us_economic_release`, `uk_monetary_policy`,
  `japan_monetary_policy` или `us_income_and_outlays`),
  `venue` и `symbol`.
- `provenance` (`recorded_fill`), уникальный `outcome_id` и `event_id`.
- `event_at`, `opened_at`, `closed_at` и `available_at` в секундах Unix UTC.
  `available_at` отмечает, когда результат сделки и его связь с событием
  стали доступны для анализа.
- `risk_usdt`, `net_pnl_usdt` после фактических издержек и
  `stressed_net_pnl_usdt` после дополнительных издержек.

Для допуска требуется минимум 20 разных сравнимых событий за 10 разных
дней UTC в окне 1095 дней. Нижняя оценка результата после стрессовых
издержек должна быть положительной. За последние 180 дней нужно не меньше
трёх сравнимых событий и положительное среднее после стрессовых издержек.
При пустой или недостаточной истории сервис остаётся в наблюдении.
Подлинность и полноту локального экспорта сервис самостоятельно подтвердить
не может.

Сигнал содержит диапазон входа, стоп, две цели, ориентировочный размер и
потенциальный убыток по сценарию. Срок действия ограничен свежестью
стакана и моментом закрытия следующей свечи. Лимит риска относится к
активным сигналам в одном журнале. Разрыв цены, фактическая очередь
ордеров и позиции в биржевом аккаунте находятся вне расчёта. Прибыльность
зависит от фактического исполнения и издержек.

## Новостной бумажный режим

Автономный режим проверяет официальные публикации NVIDIA, ФРС, ЕЦБ и BLS,
сохраняет время получения и редакцию, затем сверяет событие с закрытыми
свечами и текущим стаканом. В первом выпуске распознаются новостные темы о
руководстве NVIDIA, денежной политике и ключевых американских макроданных.
Связь корпоративного события NVIDIA с торгуемой криптопарой остаётся
исследовательской гипотезой. Для акций NVDA потребовался бы отдельный адаптер
рыночных данных. Все исполнения в этом режиме бумажные.

```sh
python -m news_paper --once
python -m news_paper --venue okx --symbol BTC/USDT
python -m news_paper --report
```

При постоянном запуске разбор новостей и сопровождение позиций работают
параллельно. Журналы по умолчанию лежат в `data/news/`. Параметр `--data-dir`
позволяет указать постоянный диск. Для разных площадок и пар используйте
разные папки, чтобы каждый процесс сопровождал собственные позиции.

Для включения команды используйте `--team` и настройте существующие
`TRADE_REVIEW_URL`, `TRADE_REVIEW_KEY`, `TRADE_REVIEW_MODEL`. На один
допущенный разбор выполняются 50 отдельных запросов с разными ролями.
Все получают подтверждённый заголовок, рыночный снимок и сопоставимые
бумажные результаты после издержек. По умолчанию одновременно выполняются
до 10 запросов. С `--concurrency 50` допустимы все 50, если провайдер
выдерживает такую параллельность. Запросы могут расходовать квоту модели.
Пилот разбирает до одного события командой за цикл. Результаты каждого
агента сохраняются в локальном журнале.

Сигнал требует достаточной бумажной истории, положительной консервативной
оценки после издержек и повторной проверки новости и котировки после
ответов команды. До этого журнал накапливает отдельные исследовательские
исполнения. Успешный сигнал фиксируется в отдельном бумажном портфеле.
